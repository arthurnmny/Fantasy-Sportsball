# Fantasy-Sportsball Repo Cleanup

Instructions for stripping this repo down to reusable code before repurposing it.

## Delete entirely

| Path | Why |
|---|---|
| `src/` (all of it: `calculators/`, `database/`, `data_collectors/`, `notifications/`, `web/`) | Every file in this tree is 0 bytes. It's leftover scaffolding from `setup_project.py` that was never filled in. |
| `templates/` (`index.html`, `results.html`) | Both files are empty. |
| `static/` (`css/style.css`, `js/main.js`) | Both files are empty. |
| `tests/` (`test_api.py`, `test_calculator.py`, `__init__.py`) | All empty — no actual tests exist. |
| `workingfiles/` | Exploratory reference dumps (`all_leagues_reference.json`, `nfl_reference.json`, `available_nfl_teams.txt`) used only for manually poking at the API. Not used by any script. |
| `logs/` | Just holds a `.gitkeep`, no logging is implemented anywhere. |

## Delete these individual files

| File | Why |
|---|---|
| `workspace1.py` | A scratch "API discovery" script for manually exploring TheSportsDB endpoints. Not used by anything else. |
| `import requests.py` | A throwaway test snippet. Also a bad filename — it shadows the `requests` package and can cause import errors if left in place. |
| `setup_project.py` | Only creates the empty folder skeleton above. No longer needed once the repo exists. |
| `data/www.thesportsdb.com_api_v1_json_123_lookupevent.php_20251008_221959.json` | A one-off cached API response from testing `fetch_leagues.py`. Regeneratable, not needed in version control. |

## Keep — this is the real project

| Path | Why |
|---|---|
| `web/app.py` | The working core: FastAPI app that reads a team watchlist CSV, checks each team's last result via TheSportsDB, caches to JSON, and runs on a weekly APScheduler cron. Build on this. |
| `fetch_league_names.py` | Working script to pull all league names from TheSportsDB into `data/league_names.txt`. |
| `fetch_teams_by_league.py` | Working script to pull teams per league into `data/league_teams.csv`, with retries/backoff and resume support. |
| `config.py` | Simple `.env`-based config pattern (API key, DB path, SMTP, schedule). Reusable as-is. |
| `requirements.txt` | Reasonable base dependency list. |
| `data/custom_league_teams.csv` | The watchlist pattern (`league,team` columns) driving `web/app.py` — decide if you keep this format or replace it. |

## Needs a decision

| Path | Why |
|---|---|
| `main.py` | A separate, self-contained NFL-teams-to-SQLite ETL demo (fetch → transform → load → query). Functional but disconnected from `web/app.py`'s logic and uses a different database file. Either merge its SQLite/query pattern into the main app, or drop it if you don't need SQL querying. |
| `fetch_leagues.py` | Overlaps with `fetch_league_names.py` — this one fetches specific *events* by ID rather than league names. Keep only if you need event-level lookups. |
| `data/latest_wins.json` | Output cache generated by `web/app.py`. Fine to keep as an example, but should probably be gitignored going forward since it's regenerated data. |

## Suggested next step

```bash
rm -rf src/ templates/ static/ tests/ workingfiles/ logs/
rm workspace1.py "import requests.py" setup_project.py
rm data/www.thesportsdb.com_api_v1_json_123_lookupevent.php_20251008_221959.json
```

Then decide on `main.py` and `fetch_leagues.py` based on whether you need SQL querying and event-level lookups in the repurposed version.
